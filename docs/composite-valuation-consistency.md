# 합성 밸류에이션 계산 일치와 상태 복구

## 원인과 재현

31번 전략은 756거래일 중앙값으로 만든 지표를 다시 1,260거래일 동안 순위화한다. 각 단계의 최소 관측 수 504개는 계산 시작 조건이며, 충분한 이력과의 결과 일치를 보장하지 않는다. 최근 1,500행만 사용하면 비교 집단과 중간 지표가 달라진다.

2026-11-03에 확보한 자료로 재현한 결과다. 점수는 전월 마지막 거래일에 계산해 다음 달에 적용한다.

| 자료 범위 | 2026-06 고점: 5/29 계산 | 2026-11 점수: 10/30 계산 | 하락 폭 |
|---|---:|---:|---:|
| 2004년 이후 이력 | 72.18253968 | 51.68253968 | 20.50000000 |
| 최근 1,500행 | 76.79761905 | 47.40256263 | 29.39505642 |

저장돼 있던 31P 고점은 두 번째 경로와 일치했다. 25점 하락 조건의 충족 여부가 바뀌므로 자료 길이 변경과 기존 상태 복구를 함께 수행한다.

## 공통 월별 점수

- 기준 시작일은 `2004-01-01`, 계산 버전은 `composite-full-history-v1`이다. 계산식과 전략 YAML은 유지한다.
- QQQ·SPY·BIL 과거 자료는 공통 KV에 보관한다. 매일 최근 7일의 겹치는 구간을 갱신하고, 월이 바뀌면 과거 이력을 재확인한다. 정상적으로 확보한 상장 이전 구간을 매 요청마다 다시 요청하지 않는다.
- 월별 점수의 입력 지문에는 전월까지의 원가격·배당·날짜를 포함한다. 월중 신규 가격은 점수 재계산을 유발하지 않으며, 확인된 과거 자료 수정은 캐시를 무효화한다.
- 점수표는 공통 저장소에서 재사용한다. 공개 `GET /valuation-scores`는 버전·입력 지문·월별 점수와 원자료 기준일만 반환한다. 개인 구독·보유량·알림 이력은 포함하지 않는다.
- 홈페이지의 전략 계산과 지표 차트는 같은 점수표를 적용한다. 서버 점수가 준비되지 않았으면 실패 상태를 표시하고 재시도하며, 짧은 로컬 이력의 재계산으로 대체하지 않는다. 서버를 사용하지 않는 오프라인 HTML은 기존 로컬 계산 경로를 유지한다.
- 과거 자료 부족, 시장 간 기준일 불일치, 전월 최종 거래일 누락은 준비 완료로 취급하지 않는다. 월말 판정에는 미국 주식시장 휴장일을 반영한다. 달력 근거: [NYSE 거래 일정](https://www.nyse.com/markets/hours-calendars), [2025-01-09 특별 휴장](https://www.nasdaqtrader.com/TraderNews.aspx?id=ETA2024-87).

## 실행 비용

긴 이력의 지표 계산과 상태 재생은 Durable Object에서 수행한다. 월별 점수는 공통으로 재사용하고, 일반 알림 평가에 전달하는 준비된 가격 자료는 종목당 최근 640행으로 제한한다. 실제 증분 평가에는 직전 평가일부터의 자료만 사용한다. 초기화와 복구는 충분한 전체 이력으로 실행한다.

공개 가격 API도 같은 과거 자료 저장소를 재사용한다. 이미 확보한 과거 자료나 아직 끝나지 않은 다음 거래일을 얻기 위해 전체 기간을 반복 요청하지 않는다. 과거 자료 보충 실패 시 기존 자료와 오류를 보존하고 재시도 시각을 따른다.

자료 보관량에는 가격뿐 아니라 준비된 지표 캐시도 포함된다. 원자료 일부를 압축한 크기를 실제 KV 저장량으로 간주하지 않는다. 초기 이력 확보와 최초 상태 재생의 비용은 매일의 증분 갱신보다 크다.

## 기존 상태 이전

1. 현재 월까지 적용한 점수 이력의 지문을 전략 상태에 기록한다. 새로운 월의 점수가 추가돼도 직전 평가일까지의 지문이 같으면 과거 재생을 생략한다.
2. 버전이나 직전 평가일까지의 점수가 다르면 그 평가일까지 전체 전략을 재생해 고점·방어 상태·연속 확인 횟수를 복구한다.
3. 보유 수량과 현금은 유지한다. 이전 계산으로 만들어진 미실행 가상 주문은 중단하고, 미발송 사건은 별도 보관한다. 기존 계산에 따른 과거 매매를 실제로 실행한 것으로 소급 처리하지 않는다.
4. 복구와 새 상태 저장은 기존 버전 확인을 거친다. 원본 상태·전달 영수증을 보존하고, 진행 중인 전달권이 있으면 만료 또는 전달 확인 뒤 다시 시도한다.
5. 복구 후 누락 구간을 올바른 점수로 평가한다. 과거 전체의 신호를 새 알림으로 일괄 발송하지 않고, 계산 복구 사실과 현재 상태·목표를 알리는 `UPDATE` 사건을 보관한다. 이 안내는 매매 명령이 아니다.
6. 복구가 완료되지 않으면 `BLOCKED`와 원인을 반환하고 잘못된 기준의 미발송 사건을 전송하지 않는다. 다음 실행에서 저장된 자료를 재사용해 재개한다.

TDF 대용지수는 각 전략의 직전 평가일에 겹치는 가격으로 연결한다. 서로 다른 전략 중 하나의 마지막 가격에 전체 전략을 일괄 연결하지 않는다.

## 검증과 운영

2026-11-04 배포: Worker `dcf4f845-c838-4d56-a0c2-d0350d36e1e1`, Pages `6cb22a6a`. Node 검사 146개와 Python 검사 40개가 통과했고 2개는 건너뛰었다. 공개 API의 6월 고점과 11월 점수 일치, 홈페이지 JS 해시, 가격 응답 및 비인증 요청 차단을 확인했다.

자동 검사는 전체 이력과 공통 점수의 일치, 1,500행 소비자에 대한 동일 점수 적용, 과거 수정에 따른 무효화, 월중 캐시 재사용, 역사 자료 보충·재시도, 초기화·복구·전달 이력 보존, 미리보기 비저장, 홈페이지 장애 표시를 포함한다.

운영 자료의 로컬 재현과 실제 workerd/SQLite Durable Object 시험에서는 31P 고점 72.18253968, 11월 점수 51.68253968, 방어 상태 `NORMAL`, 보유 수량 보존 및 오래된 쓰기 거부를 확인했다. 일반 자료 응답은 640행, 해당 누락 구간의 재평가 자료는 4행이었다. 운영 snapshot과 상세 재현 자료는 로컬 `tmp/`에만 둔다.

배포 후 기존 구독은 다음 정상 평가에서 자동 이전한다. 기존 Apps Script의 평가 요청도 처리하며, 새로운 전달권·전달 확인 및 별도 백그라운드 복구 등록은 운영 Apps Script에 최신 `Code.gs`를 저장한 뒤 활성화된다. 전략 전체 초기화는 필요하지 않다.
