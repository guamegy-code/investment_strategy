# 전략 사용자용 전략 검토 및 알림 안내

이 문서는 전략 웹페이지에서 운용할 전략을 검토하고 Telegram 알림을 받으려는 사용자를 위한
입문 안내입니다. 실제 Google Sheets 설정은
[Google Sheets 리밸런싱 알림 설정](google-apps-script/README.md)에 한 번만 정리되어 있습니다.
Cloudflare와 서버 배포는 사용자가 할 필요가 없습니다.

## 전체 흐름

1. 전략 웹페이지에서 성과와 위험, 목표 비중 변화 방식을 검토합니다.
2. 공개 전략을 그대로 쓸지, 개인 YAML 전략을 쓸지 정합니다.
3. Google Sheet에서 알림을 받을 전략 ID를 선택합니다.
4. 처음 한 번 전략 상태를 초기화하고 Telegram 연결을 테스트합니다.
5. 자동 트리거를 설치한 뒤 `알림 이력`과 `실행 로그`만 확인합니다.

준비할 것은 Google 계정과 Telegram 계정입니다. 운영자에게는 전략 웹페이지 주소,
`Code.gs`, 구독할 전략 ID, 평가 API 주소와 API 키를 받습니다.

## 1. 웹페이지에서 전략 검토

1. 운영자가 전달한 전략 웹페이지를 엽니다.
2. 후보 전략을 선택하고 최소한 다음 항목을 확인합니다.

   - 어떤 자산을 보유하는가
   - 정상·주의·하락·회복 상태에서 목표 비중이 어떻게 달라지는가
   - 최대 낙폭과 손실 구간이 감당 가능한가
   - 신호가 생긴 뒤 며칠에 나누어 실행하는가
   - 실제 계좌 상품과 화면의 기준 자산이 같은가

3. 전략 ID를 기록합니다. 알림 구독에서는 전략명이 아니라 이 ID를 사용합니다.

백테스트는 전략을 비교하기 위한 과거 자료이며 미래 성과를 보장하지 않습니다. 수익률만 보지
말고 낙폭, 거래 빈도, 방어 상태의 비중과 본인이 실제로 실행할 수 있는지도 함께 확인합니다.

## 2. 공개 전략과 개인 전략 중 선택

공개 전략을 그대로 사용하면 운영자가 알려 준 전략 ID만 있으면 됩니다.

규칙을 수정한 개인 YAML 전략은 웹페이지의 **전략 가져오기**로 먼저 검토합니다. 가져온 YAML은
그 브라우저에만 저장되며 공개 전략 목록에 자동으로 올라가지 않습니다. 알림에 사용할 때는
본인의 Google Sheet `개인 전략` 탭에 YAML을 넣습니다. 공개 Git 저장소나 Pages에 올릴 필요가
없습니다.

실제 국내 상품에 연결한 `source`/`products` 전략은 기준 전략의 시장 신호를 사용하되 알림
비중을 실제 상품 코드로 보여 줍니다. 같은 계좌에서는 기준 전략과 상품연결 전략을 동시에
구독하지 말고 실제 운용할 전략 하나를 선택합니다.

## 3. 알림 설정

[Google Sheets 리밸런싱 알림 설정](google-apps-script/README.md)의 1~8단계를 순서대로
진행합니다. 핵심 순서는 다음과 같습니다.

```text
Telegram 준비 → Apps Script 코드 붙여넣기 → 스크립트 속성 저장
→ setupSpreadsheet → 전략 선택 → initializeNotificationStates
→ 테스트 메시지 → installTriggers
```

스프레드시트에서 **확장 프로그램 → Apps Script**로 연 경우 `SPREADSHEET_ID`는 필요하지
않습니다. API 키와 Telegram 봇 토큰은 셀이 아니라 Apps Script의 **스크립트 속성**에만
저장합니다.

## 4. 알림을 받았을 때 확인할 것

### 리밸런싱 실행

실제 주문을 검토해야 하는 알림입니다. 현재·목표·증감 비중과 분할 실행 일수를 확인합니다.
알림은 주문을 자동 실행하지 않으므로 계좌의 실제 보유량, 거래 가능 시간과 세금·수수료를
확인한 뒤 사용자가 결정합니다.

### 사전주의

전략에서 중요하게 지정한 상태 변화, 상태 전환 확인의 시작 또는 목표 비중 괴리 같은 사건을
알립니다. 사전주의만으로 즉시 주문이 필요하다는 뜻은 아닙니다. 메시지에 `리밸런싱 실행`이
함께 있는지 확인합니다.

### 정기 시장 브리핑

전략 설정에 따라 일간·주간·월간으로 시장 상태와 주요 지표를 요약합니다. 일반적인 상태 변화는
즉시 알림 대신 다음 정기 브리핑에만 표시될 수 있습니다.

같은 시장 기준일에 여러 알림이 생기면 한 메시지로 합쳐질 수 있습니다. 발송된 내용은 Google
Sheet의 `알림 이력`, 실행 성공·실패는 `실행 로그`에서 다시 확인합니다.

## 전략이나 설정을 바꿀 때

| 변경 내용 | 사용자가 할 일 |
|---|---|
| 구독 전략 추가 | `알림 전략`에서 체크한 뒤 `initializeNotificationStates()` 실행 |
| 개인 YAML 계산 규칙 수정 | YAML을 바꾼 뒤 `initializeNotificationStates()` 다시 실행 |
| 구독 일시 중지 | `알림 전략`의 체크 해제 |
| Telegram 봇 또는 채팅 변경 | 스크립트 속성을 바꾸고 `sendTestMessage()` 실행 |
| `Code.gs` 업데이트 | 코드 교체 후 `setupSpreadsheet()`와 연결 테스트 실행 |
| 운영자가 API 키 교체 | 스크립트 속성의 `EVALUATION_API_KEY` 변경 |

## 보안과 지원 요청

- API 키와 Telegram 봇 토큰은 비밀번호처럼 다룹니다.
- 개인 전략 YAML은 본인만 접근할 수 있는 스프레드시트에 보관합니다.
- 오류를 운영자에게 보낼 때는 `실행 로그`의 상세 내용과 Apps Script **실행** 화면의 오류를
  전달하되 API 키, 봇 토큰과 개인 YAML은 가립니다.
- 알림 메시지만 보고 자동으로 주문하지 말고 전략 ID와 시장 기준일을 확인합니다.
